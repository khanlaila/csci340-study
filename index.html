OS Basics, Programs and CPU
Fundamentals tested on every exam.
What is an Operating System?►
OS Definition = Program that manages hardware and provides other programs with an environment to run in
Printing from MS Word►
The app shouldn’t be able to have access to your printer.

MS Word doesn’t know how to use a printer if you want to print something.

Between hardware and the app (MS Word) lies the operating system.

The app will interact with OS to deal with hardware tasks.

If multiple apps have access to the printer, there would be conflicts. The apps ask help from the OS, then the OS deals with these instructions responsibly.
What do the keyboard and mouse do?►
The keyboard and mouse don’t deal with apps directly. They interact with the OS, which then tells the app to deal with the input.
List of computer, mobile, server, and embedded operating systems►
Computer Operating Systems = Linux and all of its distros, Windows, MacOS, ChromeOS.

Mobile Operating Systems = iOS, Android.

Server Operating Systems = Linux, Windows Server, Solaris, FreeBSD.

Embedded Systems = Smaller versions of Linux, VxWorks, FreeRTOS.
Can you use a computer without an OS?►
Technically yes, but it’s not practical.
What is the OS Kernel?►
OS Kernel = A central component of the OS that performs the most important OS tasks.

The way they look and their ‘most important’ tasks depend on the OS alone.

Monolithic Kernel Approach = an OS architecture where the entire OS runs together in a single kernel space, allowing high performance due to efficient communication.

Microkernel Approach = where the kernel performs a more minimal set of functions.
List all OS functions with short descriptions.►
  • Running programs = When you click on the Brave icon, the OS knows that this icon corresponds to Brave.exe and runs it.
  • There is no CPU instruction at the end of the program that says “Program is over.” Instead of stopping itself, the program asks the OS to end the program. Hence, the OS is responsible for stopping programs too.
  • Managing the CPU = It controls what apps the CPU is executing, and for how long. The OS controls what the CPU is doing.
  • Managing RAM memory = When a program needs RAM, it’s the OS’ responsibility to decide where in RAM the program needs. The program can ask for more memory, but the OS makes the decision in the end.
  • Managing I/O devices = Regular apps don’t deal with them directly, but they ask the OS to do it for them.
  • Managing Storage = All operations with the hard-disk happen through the OS.
  • Managing Networking = Applications don’t use the internet directly, they ask the OS to send and receive messages for them.
  • User Interface = The OS’ way to let the user control the computer.
  • Security = The OS is responsible in preventing your computer from your own misuse, along with keeping viruses out, it keeps tracked who is currently logged in and what their privileges are.
  • Inter-process Communications / (IPC) = programs often interact with each other, but how do they do it? The IPC are tools that provide programs to do this.
What are safe and unsafe instructions?►
Safe instructions = User level instructions.

Unsafe instructions = Kernel level instructions.

Generally most CPU instructions are user-level.
What is dual mode and why do we have it?►
We have dual modes for safety and stability for the OS by separating user applications from critical hardware operations.

Applications that only run on user-level will still rely on kernel-level functionalities, they just don’t have control, they have to interact with the OS first.
How is dual mode implemented?►
Imagine a CPU with a bunch of bits in a special register. It is currently acting on kernel-mode, it will then accept all instructions. Meanwhile when it’s in user-mode, if it fetches kernel-level instructions, it will refuse to execute it, and alerts the OS.

When you switch modes between user and kernel mode, the OS does it. When the OS is working, the CPU is in kernel-mode. When an app runs, the CPU is in user-mode. It switches automatically to kernel-mode when a syscall happens.
What is a system call?►
System Call = a request for service from a user-level application to the OS (not a request for extra privileges, but a request to do a task).

There are CPU instructions that accommodate system calls.

The CPU runs an app, reads instructions belonging to the app in RAM and executes them. At some point a system call happens, the CPU then pauses the app and switches to run the OS. Hence, the OS that exists on RAM relies on the CPU, then the CPU switches back from the OS to running the original app. There is a switch.

Performance Overhead = how a system call takes longer to execute because of this switch.

Therefore doing things on user-level is faster because you aren’t interacting with the OS, you’re using tools available to the application. Kernel-level instructions always use system calls, hence they are slower.
Is there an OS API? What is POSIX?►
OS API = A set of tools that an OS provides for programmers to create apps for the OS, it does syscalls under the hood.

Providing classes, functions, and variables and how to use them. Some API functions are system call wrappers.

POSIX = A standard for maintaining compatibility between operating systems, there is also a POSIX API.
What is multitasking?►
Multitasking is a technique to fake the simultaneous execution of multiple programs on a single CPU core. The CPU is frequently switched between programs, giving the illusion that all programs are running at the same time.
What is virtual memory?►
Virtual memory is a technique to fake larger RAM using the hard disk. It is expensive because hard disk is slow. It does not mean the program runs from the disk — the program still runs from RAM, but unused portions can be moved to the hard disk temporarily.
What are interrupts? What is an ISR? What is the sequence of steps when an interrupt occurs?►
An interrupt is a signal sent to the CPU about an important event that needs immediate attention. Interrupts can be issued by hardware (e.g., keyboard, network card) or software.

The ISR (Interrupt Service Routine), also called the interrupt handler, is the code that runs in response to an interrupt.

Sequence:
1. Interrupt is generated
2. Signal reaches CPU — CPU pauses current execution
3. CPU runs the ISR (interrupt handler)
4. Interrupt is cleared — CPU resumes previous execution
What is a driver?►
A driver is a small program that handles communication between the OS and a hardware device.
What is a file? What is a file system? What is a logical disk?►
File = a collection of related data stored under one name.

File System = a collection of data about all files, including their coordinates (where they are stored on disk).

Logical Disk = also known as a partition. A portion of a hard disk that has its own separate file system.
What are networking protocols?►
Networking protocols = sets of rules and standards that define how data is formatted, transmitted, and received over a network. They govern the structure of messages and the order of operations.

Examples: TCP (reliable data transmission), IP (routing/addressing), HTTP/HTTPS (web), FTP (file transfer), SMTP (email), DNS (domain name resolution).
What is a GUI? What is a command line?►
GUI (Graphical User Interface) = a tool that allows you to issue instructions to the OS by manipulating graphical representations of computer components (icons, windows, buttons). Often called "bash/shell" in a text context.

Command line = a text-based interface where you type commands directly. Super useful and sometimes the only available tool. Remember Linux-style commands (ls, cd, mkdir, etc.).

Both are ways the OS provides a User Interface — the OS's way to let the user control the computer.
Processes
PCB, process states, fork/exec/exit/wait, zombies, orphans
What is a process? How is it different from a program?►
Process = a program in execution.

Program = a list of directions for the computer to execute, and it is used to manipulate data.

When apps are run, the OS looks at processes and what they need, so processes are dynamic when the OS manages them. One program can have multiple processes.

The OS needs a record for every process.
What is the PCB? Typical components?►
Process Control Block (PCB) = a record for a single process maintained by the OS. What’s in it depends on what the OS decides, typically <1 kilobyte in size.

Common things to have in the PCB:
PID = a numeric name of a process
PID of the parent = PID of a process that made another process
CPU scheduling information = OS decides which process uses which CPU part
Memory management info = addresses that were given to currently running program
List of opened files
List of requested I/O devices
Register file = copies of values in the registers
PC = program counter, showing where the execution of program code is happening right now
List the five process states and describe each.►
  • New = created but not ready to do anything.
  • Ready = process joins the ready queue, ready and willing to use the CPU.
  • Running = using the CPU right now.
  • Waiting = waiting for something not requiring CPU right now.
  • Terminated = doesn’t need anything anymore.
Ready queue vs I/O queue. How many of each?►
Ready queue = a collection of processes ready and willing to use the CPU. Typically there is one ready queue per CPU in a system.

I/O queue = a collection of processes waiting to use an I/O device.

There is 1 I/O queue for each I/O device.
What happens when a process requests I/O (blocking)? Where does it go after?►
Some processes will use I/O devices and or hard-disk, the process makes a request and stops using the CPU to join the I/O queue. The CPU switches to execute another process when this happens.

Sooner or later, the process gets permission to use the hard-disk, while the process uses the hard-disk, the process is in the Waiting State. After this, the process will want to use the CPU again, it will end up in the ready queue again.
What is a context switch? Why does it have overhead?►
Context Switch = a sequence of steps that the CPU goes through to switch execution from one process to another.

P1 → P2
Pause process 1
Save all general purpose CPU registers and PC of P1 into RAM (saving context)
Load from RAM all general purpose CPU registers and PC of P2 (loading next context)
Resume process 2

To switch execution from P1 to P2, there are 2 RAM operations.
We store context of P1 to RAM.
Then read context of P2 from RAM.
This explains why context switching takes extra time, RAM is slow compared to CPU.
Layout of a process in memory. Describe each section.►
  • Text Section = Program code (instructions).
  • Data Section = Global variables and static variables.
  • Heap = Dynamic memory (new operator). Fragmented, full of holes.
  • Stack = Local variables, function parameters, return addresses. Clean LIFO order, no holes. Each thread has its own stack.
What is fork()? Return values?►
fork() = Creates an almost exact copy of the process. Original = Parent. Copy = Child.

Returns 0 to child. Returns positive PID value to parent. After fork, both processes continue from the next instruction concurrently. Order is not guaranteed.
What is exec()? exit()? wait()?►
exec("name") = Erases all process content and starts a new program from an executable file. Typically used in child after fork().

exit() = Stops the process, reports exit status (0 = success), releases resources. Code after exit() does not run. PCB stays -- process becomes zombie until parent calls wait().

wait() = Called by parent to pause until child terminates. Receives child's exit status. Parent then continues.
Zombie process? Orphan process? Why are orphans bad?►
Zombie = Called exit() but parent has not called wait() yet. No resources, but PCB remains.

Orphan = Parent exited without calling wait(). Bad because nobody can collect exit status. System either adopts orphans or uses cascading termination (kill all descendants when parent exits).
What happens to processes when state changes? What is POSIX?►
State changes are not physical movement. The OS updates the internal data structures, like the PCB, to mark a process as Ready, Running, Waiting, or Terminated.

POSIX = Portable Operating System Interface, a set of standards that define how Unix-like operating systems should behave to maintain compatibility between systems.
Threads
Threads vs processes, shared state, std::thread
What is a thread? What do threads share vs not share?►
Threads = an independent execution of program code from a separate program counter.

Threads start with one main thread within a process, threads share:
Text Section
Data Section
Heaps

Threads do NOT share:
Stack
Each thread has its own stack, the stack is used to manage each thread's independent execution flow.

All function parameters, all local variables are private to each thread.
Why create threads instead of processes?►
Threads are memory efficient, fast to create, context switching is faster, and they have shared memory by default. Overall, there is less overhead from the OS compared to processes.
Why create processes instead of threads?►
Processes can run exec(). If one thread crashes, the whole process is stopped with all of its threads, meanwhile processes’ survivability are independent despite being more expensive, this makes them fault-independent.
TLS? Thread pool? How to create a thread with std::thread?►
Thread Local Storage = a tool that allows you to create variables that are global but still private for each thread.

Thread Pool = used for more efficient thread management, it’s a tool that creates a bunch of threads and puts them to sleep (waiting state). When a user requests new worker threads, instead of creating new threads you use these already-made ones.

#include <thread>
std::thread t1{Foo,5};
std::thread t2{Foo,56};

t1.join();
t2.join();
What does std::thread::join() do? Why do we need it?►
std::thread::join() = blocks the calling thread (pauses it) until the thread on which join() was called has finished execution.

We need join() because without it, the calling thread (usually main) may exit before the worker thread finishes. When main exits, the entire process terminates and kills all threads — causing incomplete work or undefined behavior.

#include <thread>
void Foo(int x) { /* do work */ }
int main() {
  std::thread t1{Foo, 5};
  t1.join(); // main pauses here until t1 finishes
  // only now does main continue
}
What are kernel threads? What are user threads? What are hardware threads?►
Kernel threads = managed using OS help. The OS knows about them. Slower to create and manage.

User threads = managed without OS help. Faster to manage. The OS does NOT know about them. Cannot use multiple cores. If one user thread blocks, all threads in that process block.

Hardware threads = how many threads the CPU can run simultaneously without multitasking (no context switching).
IPC + Networking
Inter-process communication, shared memory, message passing, and basic networking terms.
What is IPC? What are the two general classes of IPC?►
IPC = inter-process communications, a mechanism that allows cooperating processes to exchange data.

The two general classes are shared memory and message passing.
What is the idea of shared memory? What are its advantages and disadvantages?►
OS creates a region that multiple processes can read and write. That region is called shared memory.

Advantages: faster because the OS is only needed once to create the region.
Disadvantages: error-prone, requires synchronization and planning, and cannot be used between two different computers on a network.
What is the idea of message passing? What are the advantages and disadvantages?►
Process A passes data to the OS and the OS delivers it to process B.

Advantages: easier and less error-prone, and works well across different computers.
Disadvantages: slower than shared memory because every message goes through the OS.
Can shared memory be used by processes on two different computers?►
No. Shared memory requires direct access to the same memory, so it cannot be used over a network between two computers.
What is a network? What is an IP address? Why is an IP address not enough?►
Network = a bunch of computers connected together to exchange data.

IP address = numerical label assigned to each device connected to a network. A classic IPv4 address has 4 numbers separated by periods, each between 0 and 255.

An IP address alone is not enough because it identifies the device, not the program. You also need a port number.
What is a networking port? What are well-known ports?►
Networking port = a unique numeric identifier assigned to every process in the system that wants to use the network.

Well-known ports = ports that have been officially assigned to specific standard protocols and services. They serve predefined purposes. Examples: 80 = HTTP, 443 = HTTPS, 22 = SSH, 21 = FTP, 25 = SMTP (email), 53 = DNS. They fall in the range 0–1023.

Warning: Saying "the first 1024 ports" alone is worth 0 points on the exam. You must say they have predefined/standard purposes for specific services.
What is a networking socket? What is a server? What is a client?►
Socket = an endpoint for communication.

Networking socket = IP address + networking port, for example 55.220.0.51:81.

Server = a computer on the network that receives requests and provides services to other computers.
Client = a computer that obtains information from a server.
What is a communication protocol? What is URL? What is DNS? What is RPC?►
Communication protocol = set of rules and standards that defines how data is formatted, transmitted, and received between devices on a network.

URL = the human-readable address used to access resources on the internet.

DNS = a separate computer that takes a URL or domain name and returns the IP address of the destination computer.

RPC = Remote Procedure Call, an IPC tool that lets you start execution of a function on a faraway computer/server.
What is a network socket? What does it represent?►
A network socket is the combination of an IP address and a networking port. It identifies exactly where data should go on a machine.
Memory Management
Physical vs logical addresses, MMU, paging, TLB, page faults
What is RAM memory purpose?►
The purpose of RAM memory is to store data and program instructions that the CPU needs during execution. It's fast, temporary, and allows quick read/write access.
What is memory address? How much memory you can address with addresses of a given size (for example, 64-bit addresses)►
unique identifier used by a computer's CPU to access a specific location in the system's memory (RAM)

With N-bit addresses you can address 2^N bytes.
What is physical address?►
coordinates of a specific byte in real physical RAM. Shows bytes in the physical memory.
Why physical addresses are inconvenient for modern programs?►
Because you cannot expect your program to be located in the same location in RAM. Inconvenient for processes to deal with real memory. It causes overlap/conflicts between processes, and it’s hard to manage memory protection and isolation
What is logical address?►
Memory coordinates, the way that processes see them and it is generated by the CPU.
What is physical address space? How many physical address spaces are there in the system?►
collection of all physical addresses available in a system. 1 physical address because its only one RAM
What is logical (a.k.a. virtual) address space? How many logical address spaces are there in the system?►
Collection of all logical addresses available to a process. Each process lives in its own space illusion.
What kind of address does the CPU fetch with instructions?►
logical address
What kind of address does the CPU send to RAM with a load/store request?►
logical
What kind of address arrives to RAM with the load/store request?►
physical address
What is MMU? What is its purpose?►
Memory management unit: hardware responsible to convert logical addresses to physical address
What is contiguous memory management?►
technique that allocates each/every process in one chunk of memory.
How does the OS decide which hole to give to a process? What are Best Fit, Worst Fit, and First Fit?►
Best Fit = picks the smallest hole that is large enough for the process. Leaves tiny unusable holes — maximizes external fragmentation.

Worst Fit = picks the largest hole. Leaves a larger remainder — minimizes external fragmentation.

First Fit = picks the first hole that is big enough. Fast because it stops searching once it finds one.
What is fragmentation? What is external fragmentation? // What is internal fragmentation?►
fragmentation: phenomenal of wasting RAM memory because of inefficient usage.

External Fragmentation: type of fragmentation happens because of very small holes not allocated to any process and too small to hold any realistic large process.

internal fragmentation: type of fragmentation where RAM is wasted because we give a process more RAM than what it needs. Internal fragmentation doesn't do as much damage as external fragmentation.
What kind of fragmentation contiguous memory management suffers from?►
external fragmentation
What is paging?►
Paging is a technique that divides memory into fixed-size blocks (pages/frames). Avoids contiguous allocation issues. It gives a lot of flexibility because you can place any page in a vacant frame. If it's not being used it doesn't have to be put in memory.

kB < page size < MB → 4kB in most cases
What is page? What is frame?►
page: portions of logical address space. frame: portions of physical address space.
What kind of fragmentation paging suffers from?►
internal
How do sizes of pages and frames relate?►
pages and frames are always of the same size.
What is page offset?►
refers to how far a specific memory address is from the start of a page in a paged memory system.
What is page table?►
data structure that stores page(virtual address) to frame(physical address) mapping.
How many page tables are there in a system?►
1 for each process
What is TLB? What is its purpose?►
TLB: device inside MMU that stores most currently useful entries from page table.
What is TLB hit? What is TLB miss?►
TLB hit: situation when TLB has the required page table entry that MMU needs

TLB miss: situation when TLB doesn't have page table entry that MMU needs right now. In this case, TLB checks RAM. Expensive because it goes to RAM and get the entry back
Is it necessary to have the whole program in memory to run it? What is on-demand paging?►
No. The whole program does not need to be in RAM to run it.

On-demand paging (a.k.a. demand paging) = a memory management technique where pages are loaded into RAM only when they are needed (demanded by the CPU). Pages are not loaded at startup — only the page currently being accessed is brought into RAM. If a needed page is not in RAM, a page fault occurs and the OS fetches it from disk.
What is page fault?►
Situation when we need a page that is not in RAM right now. In this case, program pauses and OS load it from disk
What are the options for MMU to deal with the page table (we discussed three of them)? What are the disadvantagies of those options we don't use?►
1. store whole page table in MMU
2. keep whole page table in RAM
3. store only currently used portion in MMU

Disadvantages of the ones we don't use:
1. store whole page table in MMU = not good because it makes context switches slow.
2. keep whole page table in RAM = better, but still bad because it doubles the memory operations.
What are the paging formulas for page number, offset, and physical address?►
Page number = logical address ÷ page size

Offset = logical address % page size

Physical address = (frame number × page size) + offset
Synchronization
Race conditions, mutex, semaphores, deadlock
What are synchronization problems?►
Programming problems that arise when you create multithreaded code or a program that exchanges data with other programs
What synchronization hazards do you know?►
Race conditions, deadlocks, critical section problem, producer consumer / bounded buffer problem, readers writers problem, dining philosophers problem
What is a shared resource?►
Any data that two or more threads/processes can simultaneously read or write to

Global variables or shared memory
What is race condition (a.k.a. data race)?►
A scenario when a shared resource becomes corrupted because multiple threads/processes tries to access this shared resource, and at least one of them tries to modify it
Explain how race condition can happen?►
Imagine a shared int variable that is initially 0 and 2 threads, both threads have the same exact function and that is to add one to this shared int variable. If both threads try to execute at the same time, thread 1 can increment 1 to glob and then thread 2 can also increment 1 to glob (but sees the old value of glob because thread 1 hasn’t saved the value yet), so then after that thread 1 saves the value of glob as 1 but then thread 2 also saves the value of glob as 1, overwriting the data. The result is glob = 1 instead of the expected glob = 2. Thread 2 loaded the old value before Thread 1 stored its result, so both increments resulted in the same final value.

This happens because threads share the same CPU core but each thread uses its own CPU registers, but they also share the same glob variable in RAM

T2 entered T’s critical section rather than stopping to wait until T1 finishes all of its instructions, only then can T2 run in its own critical section.

To ensure critical sections don’t overlap, a mutex is a possible solution, where T1 would grab the lock to lock the shared resource, it would then proceed to finish all its instructions and when it’s done, it unlocks itself and hands the lock to T2 so T2 can do the same, now loading the updated value, T2 is responsible for both locking, doing its instructions, then unlocking, handing the lock to the next thread/process that needs to work

Since race conditions are logic errors, reproducing the bug is difficult
Can race condition happen if only one party modifies the data and others are just reading? Can race condition happen if everybody is just reading?►
Yes — if only one party modifies the data and others are just reading, a race condition can still happen. Readers might read partially updated or inconsistent values during the modification.

No — if everybody is just reading and nobody is modifying, a race condition cannot happen.
What is critical section problem?►
A problem of programming your threads/processes in such way that they do not use shared resources simultaneously
What are the three properties of a good solution to a critical section problem?►
Exclusivity → only 1 party can access a shared resource at a time
Progress → shared resource does not stay idle if somebody needs it
Bounded waiting → make sure that nobody waits forever
Explain the idea of locking shared resources.►
Answered earlier, lock needs to be responsibly handled so that a party doesn’t keep a lock (lock==TRUE) forever especially in a multi-thread/multi-process system

Lock is also a shared variable

while (lock==TRUE) {} // keep checking if the shared resource is busy or not
lock = true;
// critical section
lock = false;
What does an atomic function mean?►
Hardware-implemented function that allows us to avoid race conditions and do multi threading and shared resources

Only one atomic function can run at a time, and they are uninterruptable
What does it mean if the function is hardware implemented►
No implemented program code, no general CPU instructions in memory

Implemented via hardware circuitry and is called a single special CPU instruction
What is test_and_set instruction and what does it do?►
It’s an example implementation of an atomic function which takes a reference to a bool lock, it saves the initial value of the lock before setting it to true (which means its using a shared resource hence its locked), and then returns the original status so you know if it WAS unlocked

This function checks the current lock status, if the lock is unlocked then it locks it again. This function prevents race conditions on the lock itself
bool test_and_set(bool& lock) {
bool original = lock;
lock = true;
return original; }
Simple solution of the critical section problem using test_and_set instruction. What is suboptimal in this solution?►
while (test_and_set(globLock)) {};
// CRITICAL SECTION
globLock = false;
The suboptimal part is that it doesn’t have the “bounded waiting” property, in other words, it is not starvation-free.
Solution of the critical section problem using test_and_set instruction with the "bounded waiting" property.►
// 4 threads so N=4, thread indices 0,1,2,3
// Initial states → lock = false, wait[] = {false,false,false,false}
bool lock = false;      // true = resource locked, false = resource free
bool wait[N] = {false}; // i=true if thread i is waiting for/using a resource
// for thread i:
wait[i] = true; // thread i wants to use the resource
while (wait[i] && test_and_set(lock)) {}; // spin until lock acquired
wait[i] = false; // not waiting for lock anymore
// CRITICAL SECTION
int j = (i + 1) % N; // scan for the next waiting thread
while (wait[j] == false && j != i)
  j = (j + 1) % N;
if (j != i) wait[j] = false; // hand the lock to the next waiting thread 
else lock = false; // no one else waiting, release lock for anyone
What does busy waiting mean? What is spinlock? Why is it inefficient? When is it still good?►
Busy Waiting is a method of waiting that needs constant CPU usage

A spinlock is a synchronization tool that implements busy waiting under the hood

It’s inefficient because of the sole fact that it forces the CPU to stay active

But they’re still good when you expect a very short wait, it’s cheaper to do this than performing context switching to other processes
What is mutex? What does the process do if it needs a mutex that is busy?►
A mutual exclusion lock

For processes that needs a busy mutex, the process will pause and wait for the mutex to be free again before proceeding further
Be ready to use C++ std::mutex to protect critical sections of code.►
#include <mutex>
#include <thread>
int glob = 0;
std::mutex m; // shared lock to protect glob
void Incr() {
  for(int i = 0; i < 1000; i++)
    m.lock();
    glob++; // race condition happens if m isn’t implemented
    m.unlock(); }
int main() {
  std::thread t1(Incr);
  std::thread t2(Incr);
  t1.join();
  t2.join();
  std::cout << glob; }
What is a semaphore? What do wait() and signal() do?►
A semaphore is an integer value accessed through 2 atomic functions:

wait() = if the value is positive, decrease it by 1 and continue; otherwise stop and wait.

signal() = increase the value by 1.

Example: Semaphore S = 2; wait(S); ... signal(S);
Producer-Consumer problem (a.k.a. Bounded Buffer problem) and its solution.►
It’s a problem because both the producer and consumer use the same buffer, which risks race conditions when reading/writing. Overflows and underflows must be addressed, and sleep/wake mechanics must be implemented.

If buffer full, producer sleep. If buffer empty, consumer sleep

Use 2 semaphores, which are int values that can be incremented/decremented.

Waiting → if the value is positive, decrement by 1 and continue
Signal → increment by 1
#include <semaphore>
Semaphore FULL = 0;  // # of items in buffer
Semaphore EMPTY = N; // # of free spaces in buffer
// producer can’t add to a full buffer
wait(EMPTY);   // decrease # of free spaces, smth has been added
signal(FULL);  // thus capacity increases
// consumer can’t take from an empty buffer
wait(FULL);    // decrease # of occupied spaces, smth has been removed
signal(EMPTY); // add an instance of free space
Readers-Writers problem and its solution.►
Readers can read at the same time, writers cannot write at the same time, reading and writing cannot happen at the same time

Writers are at a disadvantage because imagine a scenario where one writer wants to write but there’s a reader reading. Another writer wants to write so that has to wait too, then another reader joins but because of the reader's priority it can just read immediately, this approach can potentially starve writers.
// SOLUTION FOR SHARED DATA
mutex access;        // visible to all threads
int num_readers = 0; // shared between readers, protect from data race
mutex read_guard;    // protect readers from data race
// SOLUTION FOR READERS, THREAD SAFE AS ONLY 1 THREAD CAN GRAB READ_GUARD FOR ITSELF
read_guard.lock();
num_readers++;
if (num_readers == 1) access.lock(); // for the first reader
read_guard.unlock();
// start reading, then done reading
read_guard.lock();
num_readers--;
if (num_readers == 0) access.unlock(); // for the last reader
read_guard.unlock();
// SOLUTION FOR WRITERS, one-at-a-time access, 
access.lock();
// write
access.unlock();
Describe Dining Philosophers problem. What do philosophers represent? What do chopsticks represent?►
The problem is to arrange the best way for the philosophers to get the chopsticks

Philosophers are threads/processes, where each philosopher is an independent execution unit, they think (do work) and get hungry (wants to access a resource)

Chopsticks represent mutex locks / shared resources, each chopstick is a lock controlling access to a shared resource. Philosophers need both the left and right chopstick to eat (use resource), but only one philosopher can hold each chopstick at a time

The number of chopsticks and philosophers are the same

Each philosopher needs to grab the left chopstick, then grab the right, EAT, then put down the left chopstick, then put down the right chopstick
What is a deadlock?►
A deadlock occurs when all parties block each other and nobody progresses

Deadlocks don’t occur when a party waits for another, only when all parties wait on each other and they get stuck infinitely.
Name 3 approaches to solving dining philosophers problem.►
1. Add an extra chopstick (shared resource)
There will always be a philosopher that can progress forward with 2 chopsticks — deadlock is impossible if at least 1 philosopher can move forward.

2. Pick chopsticks simultaneously
Pick both chopsticks within a critical section at the same time. Practically meaningful, but not ideal — only one philosopher will be able to grab chopsticks at a time, everyone else must wait even if they don't share common chopsticks, causing unnecessary waiting.

3. Asymmetric solution
At least 1 philosopher grabs chopsticks in a different order (e.g., starts with the right while others start with the left, and vice versa). This breaks the circular wait condition, making deadlock impossible.
CPU Scheduling
How the OS picks the next process and how long it gets the CPU.
What is the CPU scheduling about?►
is about OS choosing which process is the next one to use the CPU and for how long. OS has a component called short term scheduler, which is a component responsible to choose the next process to use the CPU.
What are the three types of schedulers?►
Short-term scheduler (CPU scheduler) = decides which process in the ready queue gets the CPU next. Runs very frequently (milliseconds). This is what we study most in CPU scheduling algorithms (FCFS, SJF, RR, Priority).

Medium-term scheduler (Midterm scheduler) = handles swapping — moves processes in and out of RAM to/from disk to manage the degree of multiprogramming. Runs less frequently.

Long-term scheduler (Job scheduler) = decides which processes are admitted into the ready queue from the job pool. Controls how many processes are in memory at once. Runs infrequently.
What does the choice of a specific CPU scheduling algorithm depend on?►
there are different CPU scheduling algorithms such as our home project, or having a ready queue which is FIFO. Different OS, use different CPU scheduling algorithm depending on the purpose.
What is CPU burst? What is I/O burst?►
CPU burst: period of time when a process wants to use CPU only. think about your program running, and it needs to do I/O operation.

I/O burst: period of time when a process wants to use an I/O device. what happens after it? goes back to the ready queue.
Why can it be beneficial to schedule short CPU burst processes to the CPU before long CPU burst processes?►
short CPU burst processes before the long ones because you keep the ready queue short and minimize the waiting time.
What does it mean a CPU scheduling algorithm is preemptive or non-preemptive?►
Preemptive: when a process is in the middle of the CPU burst and is sent back to the ready queue because the CPU is needed for something more important.

non-preemptive: means that if a process gets to use the CPU, it runs until the end/ as long as it needs.
What does it mean a CPU scheduling algorithm is starvation free?►
no process in the ready queue will wait forever, the OS uses such a method that every process in the ready queue will use the CPU, no one can wait for the CPU forever. We don't care about waiting, but about not waiting for too long. It is nice to have it, but if we don't have this property it is also ok.
First-Come-First-Served algorithm. Its idea, its advantages and disadvantages.►
The idea is to treat the ready queue as a real line and it is non preemptive.

Advantages:
fast: to choose the next one to use the CPU
starvation- free

Disadvantages:
long waiting times: can keep ready queue long
Shortest Job First (SJF) algorithm. Its idea, its advantages, and disadvantages.►
The process with the shortest CPU burst goes first. Has 2 versions: preemptive and non-preemptive. The preemptive version minimizes average waiting time. "Arrived" means when the process enters the ready queue.

Advantages:
minimizes average waiting time (preemptive version)

Disadvantages:
need to know the length of CPU bursts in advance, which is hard to predict
Round-Robin algorithm. Its idea, its advantages, and disadvantages.►
The idea is to treat the ready queue as a real line but this one is preemptive.

There is a time slice- max amount of time that a process can use the CPU in one take. After it runs the time slice amount, it goes to the ready queue and waits and finishes the remaining.
Example: time slice = 100ms, CPU burst = 150ms. It runs 100ms, then go to the back of the ready queue, and wait. It finished the remaining 50ms.

Advantages:
fast: to choose the next one to use the CPU
starvation- free
it is fair

Disadvantages:
long waiting times: can keep the ready queue long.
Priority scheduling. Its idea, its advantages, and disadvantages.►
Every process has a priority, and it specifies how important a process is

advantages:
Give priority to the process with the highest priority.
It allows us to give priority to processes that we consider important.

disadvantages:
not starvation- free
Aging.►
method to fight the starvation problem. priority increases by one if it sits there for a certain amount of seconds/time.
Priority inversion and priority donation.►
Priority Inversion: is a bad situation when a higher priority process waits for a lower priority process without a good reason. There is no reason for high to wait for medium.

Priority donation: method to counter/fix priority inversions. As long as high waits for low, low process becomes as important as high.
Real-time scheduling.►
real-time scheduling is an approach where the OS ensures that the real-time process meets the execution deadline. Real time process is a process that has cpu scheduling deadline. OS should know about real time programs
Soft and hard real-time systems.►
soft real-time: means OS knows about the existence of real time processes, and that they require special attention. I will try to meet the CPU scheduling deadline of a process, if I don't meet it, then i will just leave it there. But it gives no guaranties.

hard real-time: the whole system has to meet the CPU scheduling deadline of processes and not meeting them is consider not acceptable.

Example setup for all Gantt charts: 3 processes arrive at t=0: P1 (burst=8, priority=2), P2 (burst=4, priority=1 = highest), P3 (burst=2, priority=3 = lowest). Lower priority number = higher priority. Scale: 1 time unit = 25 px.
FCFS Gantt Chart — Non-preemptive, Starvation-free►
Arrival order: P1, P2, P3. Each process runs to completion before the next one starts.

Waiting times: P1=0, P2=8, P3=12  |  Avg WT = (0+8+12)/3 = 6.67
Starvation-free because every process in the queue is guaranteed a turn eventually.
SJF Non-preemptive Gantt Chart — Non-preemptive, NOT starvation-free►
Shortest burst first: P3(2) → P2(4) → P1(8). Once a process starts, it runs to completion.

Waiting times: P3=0, P2=2, P1=6  |  Avg WT = (0+2+6)/3 = 2.67 (best of all these examples)
Not starvation-free: if short jobs keep arriving continuously, P1 (long job) may never get the CPU.
Round-Robin Gantt Chart (quantum=3) — Preemptive, Starvation-free►
Time slice = 3 units. Each process runs for up to 3 units, then goes to the back of the queue.
P1(0→3, 5 left), P2(3→6, 1 left), P3(6→8, done), P1(8→11, 2 left), P2(11→12, done), P1(12→14, done)

Waiting times: P1=14−8=6, P2=12−4=8, P3=8−2=6  |  Avg WT = (6+8+6)/3 = 6.67
Starvation-free: every process cycles through the queue — no one waits forever.
Priority Scheduling Gantt Chart (non-preemptive) — Non-preemptive, NOT starvation-free►
Priority order: P2(1=highest) → P1(2) → P3(3=lowest). Highest-priority process runs first to completion.

Waiting times: P2=0, P1=4, P3=12  |  Avg WT = (0+4+12)/3 = 5.33
Not starvation-free: P3 (priority 3) could wait indefinitely if high-priority processes keep arriving. Solution: aging (gradually increase priority of long-waiting processes).
How to calculate waiting time and turnaround time from a Gantt chart►
Turnaround time = completion time − arrival time
Waiting time = turnaround time − CPU burst time = completion time − arrival time − burst

If all processes arrive at t=0:   waiting time = completion time − burst time

FCFS example:
P1: completes at 8, burst=8 → WT = 8−8 = 0
P2: completes at 12, burst=4 → WT = 12−4 = 8
P3: completes at 14, burst=2 → WT = 14−2 = 12
Average WT = (0+8+12)/3 = 6.67

For processes NOT arriving at t=0: waiting time = (start time − arrival time) + any later queue time.

Both midterms had a fork question worth 15 points. Practice until this is automatic.
Key rules: fork() returns 0 to child, positive PID to parent. After fork(), BOTH processes continue from the next instruction. Order between processes is NOT guaranteed. if(fork()) = parent runs if-body. if(!fork()) = child runs if-body.
Problem 1 -- Straight forks, no if
fork(); // A
cout << "1" << endl;
fork(); // B
cout << "2" << endl;
How many total processes run?
How many times is "1" printed?
How many times is "2" printed?
Walk-through:
Original and Child-A both continue after fork A.
fork B fires in both processes. Each child of B just prints "2" and finishes. Each parent of B prints "1" then "2".

Process tree:
Original
  Child-of-A
    Child-of-B-from-Child-A
  Child-of-B-from-Original
Total processes: 4
"1" is printed 2 times.
"2" is printed 4 times.
One valid output: 12 12 2 2

if (fork()) // A

Give one possible output
Walk-through:
Fork A: Original (parent, fork != 0 is true) enters if-body and prints "1". Child-of-A (fork == 0, goes to else) prints "2" then hits fork B.
Fork B: Only in the else-block. Child-of-A and its new Child-of-B both continue.
Fork C: Outside the if-else, runs in ALL processes. Original, Child-of-A, and Child-of-B all hit fork C, each spawning one more child. Every process prints "3".

Process tree:
Original                  -- prints 1, 3
  Child-of-A               -- prints 2, 3
    Child-of-B              -- prints 3
      Child-of-C-of-B       -- prints 3
    Child-of-C-of-A         -- prints 3
  Child-of-C-of-Original   -- prints 3
Total processes: 6
"1" is printed by the original (parent) only.
One valid output: 13 23 3 3 3 3

cout << "1" << endl;
if (fork()) { // A -- parent enters if, child enters else
    cout << "2" << endl;
} else {
    fork(); // B
    fork(); // C
}

How many times is "1" printed?
Give one possible output
Walk-through:
"1" runs before any fork -- so only the original process prints it. Then fork A fires.
Original (parent, fork() truthy) enters if-body: prints "2" then "3".
Child-of-A (fork() = 0, falsy) enters else-body: hits fork B, then fork C.
Fork B: Child-of-A spawns Child-of-B. Both continue to fork C.
Fork C fires in Child-of-A AND Child-of-B, spawning two more processes.
Everyone eventually reaches cout "3".

Process tree:
Original                -- prints 1, 2, 3
  Child-of-A             -- prints 3 (hits B and C in else)
    Child-of-B            -- prints 3
      Child-of-C-of-B     -- prints 3
    Child-of-C-of-A       -- prints 3
Total: 5 processes.
"1" prints 1 time (before any fork).
"3" prints 5 times (every process reaches it).

Review -- Fundamentals
These are the "Review Old Items" from the study guide. Know these cold -- they are fair game on a cumulative final.
What is a program? What is data?►
Program = list of directions for the computer to execute, and it is used to manipulate data.

Data = whatever it is in the computer but the numbers.
What does it mean to run a program? What component executes it? Where are running programs stored?►
Running a program means taking the code of the program and executing it until the end of the program.

The CPU is the hardware responsible to execute the program.

The running program is stored in memory, specifically in RAM. The RAM also stores the data the program uses while it runs.
What do we know about RAM? What is a memory stall?►
RAM = random-access, slow, and volatile. It is meant to store data, and the CPU takes data from it. It takes roughly the same amount of time to access data no matter where the data is located.

Memory stall = unlucky scenario when the CPU pauses to wait for the RAM to deliver necessary data.
What is cache memory? What is its purpose?►
Cache memory = memory device that makes interaction between the CPU and the RAM memory faster. The CPU checks cache first. If cache does not contain what the CPU needs, it goes to RAM.

Cache memory stores the most recent data and instructions used.
What is ROM memory? What does it store?►
ROM = read-only memory. It is a separate device/chip that stores programs necessary to start the computer. When the computer starts, the CPU begins fetching information from the ROM.
What is an executable file?►
An executable file contains machine code instructions for the CPU to execute.
How do speeds of CPU, RAM and hard disk compare?►
CPU > RAM > hard disks.

SSD is faster than HDD.
What is a machine cycle? What are its steps?►
Machine cycle = a sequence of steps that the CPU goes through in order to execute a single instruction.

Basic steps:
  • Fetch = take the instruction
  • Decode = prepare the CPU to execute
  • Execute = do what the instruction says
  • Write-back = put the result somewhere
What is CPU frequency? What does it measure? What is a CPU clock? What is a CPU core?►
Frequency measures how many signal CPU clocks per second. The measurement unit is Hz.

CPU clock = device in the CPU that generates synchronization pulses/signals.
CPU frequency = how often that signal happens.
CPU core = a small individual CPU inside of a CPU. Quad-core means 4 subCPUs. Octa-core means 8 subCPUs.
What is a byte? What is a bit? How many bits in a byte? How many bits in 1 KB?►
Bit = The smallest unit of data. Either 0 or 1.

Byte = 8 bits. The standard unit of memory addressing.

1 KB = 1,024 bytes = 1,024 x 8 = 8,192 bits.

Memory sizes: 1 KB = 1,024 bytes / 1 MB = 1,024 KB / 1 GB = 1,024 MB / 1 TB = 1,024 GB.
What is a memory address? What is the address of a larger chunk of memory?►
unique identifier used by a computer's CPU to access a specific location in the system's memory (RAM)

The memory address of a larger chunk of memory is the address of the first byte of that chunk.
What is the length of a memory address? What does "32-bit address" mean? How much memory can you address?►
Length of a memory address = The number of bits used to represent an address.

32-bit address = Each address is 32 bits long. With 32 bits you can represent 2^32 unique addresses = 4,294,967,296 = about 4 GB of addressable memory. This is why old 32-bit systems were limited to 4 GB of RAM.

64-bit address = 2^64 unique addresses = an astronomically large amount of memory (16 exabytes -- far more than any current system has).

Formula: with N-bit addresses you can address 2^N bytes.
What is the relationship between a C++ variable, RAM and memory address? What is a C++ pointer?►
When you declare a variable in C++, the compiler works with the OS and allocates space in RAM for that variable, and it assigns a memory address to that variable to find it in RAM. Once the program compiles, the variable turns into the corresponding memory address.

C++ pointer = a variable that stores the address of another variable. Pointers are normally 4 bytes but expect something like 8 bytes at least.
Common sizes of C++ data types. Does signed/unsigned affect size?►
  • char = 1 byte (8 bits)
  • short = 2 bytes (16 bits)
  • int = 4 bytes (32 bits)
  • long = 4 or 8 bytes (platform-dependent)
  • long long = 8 bytes (64 bits)
  • float = 4 bytes (32 bits)
  • double = 8 bytes (64 bits)
Signed/unsigned does NOT affect size -- int, signed int, and unsigned int are all 4 bytes. Signed/unsigned only affects the range of values (signed can be negative, unsigned cannot but gets double the positive range).
Hexadecimal numbers -- why do we use them? How do we convert hex to binary quickly?►
Why hex? = Hexadecimal (base 16) is a compact way to represent binary. Each hex digit maps exactly to 4 binary bits, making it much shorter than binary to write while still being easy to convert.

Quick conversion = Replace each hex digit with its 4-bit binary equivalent:
0=0000  1=0001  2=0010  3=0011
4=0100  5=0101  6=0110  7=0111
8=1000  9=1001  A=1010  B=1011
C=1100  D=1101  E=1110  F=1111
Example: 0xFF = 1111 1111 = 255 in decimal.
Example: 0x1A = 0001 1010 = 26 in decimal.
What is "little-endian"? (appeared on version 2 midterm)►
Endianness = The order in which bytes of a multi-byte value are stored in memory.

Little-endian = The least significant byte (the smallest part) is stored at the lowest memory address. Most modern CPUs (including x86/x64) use little-endian.

Example: the int value 0x12345678 stored at address 1000:
  • Address 1000: 0x78 (least significant)
  • Address 1001: 0x56
  • Address 1002: 0x34
  • Address 1003: 0x12 (most significant)
Big-endian = Most significant byte at lowest address (the "natural" reading order).
What is a word? What is the PC (Program Counter)?►
Word = The natural data size the CPU processes in one operation. On a 32-bit system a word is 4 bytes; on a 64-bit system a word is 8 bytes.

Program Counter (PC) = A special CPU register that holds the memory address of the next instruction to be fetched and executed. After each instruction, the PC automatically increments to point to the next one. It is saved and restored during context switches.
What language does the CPU understand? How do we run higher-level programs?►
The CPU only knows machine language.

To run programs written in higher-level languages, we use a compiler or interpreter.

Compiler = translates the entire program to machine language prior to execution. Advantage: faster. Disadvantage: platform specific. Examples: C++, C, Rust, Assembly.

Interpreter = converts and executes the source code line by line. Advantage: portable. Disadvantage: slower. Examples: Java, Python, JavaScript, C#.
Stack overflow -- what is it and what causes it?►
The stack has a fixed size limit set by the OS. If a program exceeds this limit (usually from infinite or very deep recursion, or allocating too many large local variables), the stack runs out of space.

This causes a stack overflow, which crashes the program. This is why you should not allocate very large arrays as local variables -- put them on the heap with new instead.
Do processes physically move in RAM when their state changes?►
No. When a process changes state (e.g., from Running to Waiting), the OS simply updates the state field in its PCB. The process stays in the exact same location in RAM throughout.

Visualizations that show processes physically moving between boxes (like moving into the I/O queue box) are simplifications for clarity. No actual movement of data in RAM happens. The "queues" are just lists of PCB references maintained by the OS.
Copy-on-write optimization for fork() + exec()►
When fork() is called, the OS creates a copy of the process -- but making a full copy of all memory is expensive.

Copy-on-write (COW) = An optimization where the OS does NOT immediately copy the memory on fork(). Instead, both parent and child share the same memory pages, marked as read-only. A copy is only made when one of them tries to write to a page.

This is especially useful when fork() is immediately followed by exec(), because exec() replaces all memory anyway -- so no copy was ever needed. The OS detects this and skips copying entirely.
Ready queue -- how many do we expect in the system?►
Typically, there is one ready queue per CPU in a system.
How does memory look for programmers?►
Memory looks like a linear array of bytes. Each byte has a unique memory address, starting from address 0 and going up. To access any piece of data, you use its memory address.
Can memory contain nothing at all?►
No. Every bit in memory is always either 0 or 1 — it can never be "empty" or "nothing." Even uninitialized memory contains some bit pattern (often garbage values or zeros depending on the OS). Memory is always in some state; there is no "blank" state.
How long should memory addresses be to address a given amount of memory?►
To address N bytes of memory, you need addresses that are at least log₂(N) bits long.

In practice: addresses must be long enough that 2^(address length) ≥ N.

Examples:
  • To address 4 GB (2³² bytes) → need 32-bit addresses
  • To address 1 GB (2³⁰ bytes) → need 30-bit addresses
  • To address 256 bytes (2⁸) → need 8-bit addresses
