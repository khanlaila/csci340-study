OS Basics, Programs and CPU
Fundamentals tested on every exam.
What is an Operating System?►
OS Definition = Program that manages hardware and provides other programs with an environment to run in
Printing from MS Word►
The app shouldn’t be able to have access to your printer.

MS Word doesn’t know how to use a printer if you want to print something.

Between hardware and the app (MS Word) lies the operating system.

The app will interact with OS to deal with hardware tasks.

If multiple apps have access to the printer, there would be conflicts. The apps ask help from the OS, then the OS deals with these instructions responsibly.
What do the keyboard and mouse do?►
The keyboard and mouse don’t deal with apps directly. They interact with the OS, which then tells the app to deal with the input.
List of computer, mobile, server, and embedded operating systems►
Computer Operating Systems = Linux and all of its distros, Windows, MacOS, ChromeOS.

Mobile Operating Systems = iOS, Android.

Server Operating Systems = Linux, Windows Server, Solaris, FreeBSD.

Embedded Systems = Smaller versions of Linux, VxWorks, FreeRTOS.
Can you use a computer without an OS?►
Technically yes, but it’s not practical.
What is the OS Kernel?►
OS Kernel = A central component of the OS that performs the most important OS tasks.

The way they look and their ‘most important’ tasks depend on the OS alone.

Monolithic Kernel Approach = an OS architecture where the entire OS runs together in a single kernel space, allowing high performance due to efficient communication.

Microkernel Approach = where the kernel performs a more minimal set of functions.
List all OS functions with short descriptions.►
  • Running programs = When you click on the Brave icon, the OS knows that this icon corresponds to Brave.exe and runs it.
  • There is no CPU instruction at the end of the program that says “Program is over.” Instead of stopping itself, the program asks the OS to end the program. Hence, the OS is responsible for stopping programs too.
  • Managing the CPU = It controls what apps the CPU is executing, and for how long. The OS controls what the CPU is doing.
  • Managing RAM memory = When a program needs RAM, it’s the OS’ responsibility to decide where in RAM the program needs. The program can ask for more memory, but the OS makes the decision in the end.
  • Managing I/O devices = Regular apps don’t deal with them directly, but they ask the OS to do it for them.
  • Managing Storage = All operations with the hard-disk happen through the OS.
  • Managing Networking = Applications don’t use the internet directly, they ask the OS to send and receive messages for them.
  • User Interface = The OS’ way to let the user control the computer.
  • Security = The OS is responsible in preventing your computer from your own misuse, along with keeping viruses out, it keeps tracked who is currently logged in and what their privileges are.
  • Inter-process Communications / (IPC) = programs often interact with each other, but how do they do it? The IPC are tools that provide programs to do this.
What are safe and unsafe instructions?►
Safe instructions = User level instructions.

Unsafe instructions = Kernel level instructions.

Generally most CPU instructions are user-level.
What is dual mode and why do we have it?►
We have dual modes for safety and stability for the OS by separating user applications from critical hardware operations.

Applications that only run on user-level will still rely on kernel-level functionalities, they just don’t have control, they have to interact with the OS first.
How is dual mode implemented?►
Imagine a CPU with a bunch of bits in a special register. It is currently acting on kernel-mode, it will then accept all instructions. Meanwhile when it’s in user-mode, if it fetches kernel-level instructions, it will refuse to execute it, and alerts the OS.

When you switch modes between user and kernel mode, the OS does it. When the OS is working, the CPU is in kernel-mode. When an app runs, the CPU is in user-mode. It switches automatically to kernel-mode when a syscall happens.
What is a system call?►
System Call = a request for service from a user-level application to the OS (not a request for extra privileges, but a request to do a task).

There are CPU instructions that accommodate system calls.

The CPU runs an app, reads instructions belonging to the app in RAM and executes them. At some point a system call happens, the CPU then pauses the app and switches to run the OS. Hence, the OS that exists on RAM relies on the CPU, then the CPU switches back from the OS to running the original app. There is a switch.

Performance Overhead = how a system call takes longer to execute because of this switch.

Therefore doing things on user-level is faster because you aren’t interacting with the OS, you’re using tools available to the application. Kernel-level instructions always use system calls, hence they are slower.
Is there an OS API? What is POSIX?►
OS API = A set of tools that an OS provides for programmers to create apps for the OS, it does syscalls under the hood.

Providing classes, functions, and variables and how to use them. Some API functions are system call wrappers.

POSIX = A standard for maintaining compatibility between operating systems, there is also a POSIX API.
Processes
PCB, process states, fork/exec/exit/wait, zombies, orphans, IPC
What is a process? How is it different from a program?►
Process = a program in execution.

When apps are run, the OS looks at processes and what they need, this makes processes dynamic when the OS manages them. One program can have multiple processes (like how Chrome can have 5 different processes even when only 1 window is open).

The OS needs a record for every process.
What is the PCB? Typical components?►
Process Control Block (PCB) = a record for a single process maintained by the OS. What’s in it depends on what the OS decides, typically <1 kilobyte in size.

Common things to have in the PCB:
PID = a numeric name of a process
PID of the parent = PID of a process that made another process
CPU scheduling information = OS decides which process uses which CPU part
Memory management info = addresses that were given to currently running program
List of opened files
List of requested I/O devices
Register file = copies of values in the registers
PC = program counter, showing where the execution of program code is happening right now
List the five process states and describe each.►
  • New = created but not ready to do anything.
  • Ready = process joins the ready queue, ready and willing to use the CPU.
  • Running = using the CPU right now.
  • Waiting = waiting for something not requiring CPU right now.
  • Terminated = doesn’t need anything anymore.
Ready queue vs I/O queue. How many of each?►
Ready queue = a collection of processes ready and willing to use the CPU.

I/O queue = a collection of processes waiting to use an I/O device.

There is 1 I/O queue for each I/O device.
What happens when a process requests I/O (blocking)? Where does it go after?►
Some processes will use I/O devices and or hard-disk, the process makes a request and stops using the CPU to join the I/O queue. The CPU switches to execute another process when this happens.

Sooner or later, the process gets permission to use the hard-disk, while the process uses the hard-disk, the process is in the Waiting State. After this, the process will want to use the CPU again, it will end up in the ready queue again.
What is a context switch? Why does it have overhead?►
Context Switch = a sequence of steps that the CPU goes through to switch execution from one process to another.

P1 → P2
Pause process 1
Save all general purpose CPU registers and PC of P1 into RAM (saving context)
Load from RAM all general purpose CPU registers and PC of P2 (loading next context)
Resume process 2

To switch execution from P1 to P2, there are 2 RAM operations.
We store context of P1 to RAM.
Then read context of P2 from RAM.
This explains why context switching takes extra time, RAM is slow compared to CPU.
Layout of a process in memory. Describe each section.►
  • Text Section = Program code (instructions).
  • Data Section = Global variables and static variables.
  • Heap = Dynamic memory (new operator). Fragmented, full of holes.
  • Stack = Local variables, function parameters, return addresses. Clean LIFO order, no holes. Each thread has its own stack.
What is fork()? Return values?►
fork() = Creates an almost exact copy of the process. Original = Parent. Copy = Child.

Returns 0 to child. Returns positive PID value to parent. After fork, both processes continue from the next instruction concurrently. Order is not guaranteed.
What is exec()? exit()? wait()?►
exec("name") = Erases all process content and starts a new program from an executable file. Typically used in child after fork().

exit() = Stops the process, reports exit status (0 = success), releases resources. Code after exit() does not run. PCB stays -- process becomes zombie until parent calls wait().

wait() = Called by parent to pause until child terminates. Receives child's exit status. Parent then continues.
Zombie process? Orphan process? Why are orphans bad?►
Zombie = Called exit() but parent has not called wait() yet. No resources, but PCB remains.

Orphan = Parent exited without calling wait(). Bad because nobody can collect exit status. System either adopts orphans or uses cascading termination (kill all descendants when parent exits).
What is IPC? Two general classes?►
IPC = Tools that allow processes to exchange data.

Message Passing = Pass message to OS, OS delivers to other process. Slower (syscall), safer, works across different computers.

Shared Memory = Processes share a memory region directly. Faster (OS help only once), harder to program correctly, same computer only.
Threads and Networking
Threads vs processes, DNS, ports, sockets, std::thread
What is a thread? What do threads share vs not share?►
Threads = an independent execution of program code from a separate program counter.

Threads start with one main thread within a process, threads share:
Text Section
Data Section
Heaps

Threads do NOT share:
Stack
Each thread has its own stack, the stack is used to manage each thread's independent execution flow.

All function parameters, all local variables are private to each thread.
Why create threads instead of processes?►
Threads are memory efficient, fast to create, context switching is faster, and they have shared memory by default. Overall, there is less overhead from the OS compared to processes.
Why create processes instead of threads?►
Processes can run exec(). If one thread crashes, the whole process is stopped with all of its threads, meanwhile processes’ survivability are independent despite being more expensive, this makes them fault-independent.
TLS? Thread pool? How to create a thread with std::thread?►
Thread Local Storage = a tool that allows you to create variables that are global but still private for each thread.

Thread Pool = used for more efficient thread management, it’s a tool that creates a bunch of threads and puts them to sleep (waiting state). When a user requests new worker threads, instead of creating new threads you use these already-made ones.

#include <thread>
std::thread t1{Foo,5};
std::thread t2{Foo,56};

t1.join();
t2.join();
What is an IP address? Why is it not enough alone?►
IP Address = Each number is an unsigned byte integer (0 - 255), helps to identify the destination of a computer.

An IP address alone isn’t enough to send a message.
Networking port? Well-known ports?►
Networking Port = a unique numeric identifier given to every process that wants to use the network. An IP address and a port is considered a full address.

Well Known Networking Port = networking ports reserved for a specific purpose.

Browser knows that port:80 is reserved for HTTP requests, if there’s a web server listening for incoming web page requests, it will be listening on port 80.
What is a network socket? What is DNS?►
Network Socket = a combination of IP address and networking port.

DNS Server = DNS servers function as the internet’s phonebook, translating human-readable domain names (like example.com) into machine-readable IP addresses.
Memory Management
Physical vs logical addresses, MMU, paging, TLB, page faults
Physical address vs logical address. How many of each exist?►
Logical Memory Address can also be called a Virtual Memory Address.

Physical Memory Address = the real address of the real RAM device.

There is only one physical address space in your system, because there is only one physical RAM device in your PC.
What kind of address does the CPU use? What arrives at RAM?►
When CPU fetches address they access using logical address from the instruction.

Addresses used in instructions are logical addresses. The MMU converts them to physical addresses, and the physical address arrives at RAM.
What is the MMU?►
Memory Management Unit = a device that converts logical addresses to physical addresses.

This device is responsible for dealing with addresses, before running a program, the OS calls the MMU saying it’s about to run a program, and says this program believes it owns all the memory in the computer, the OS tells the MMU to catch addresses that running programs use and convert them from program specific addresses to physical memory addresses.
What is contiguous memory allocation? What fragmentation?►
Contiguous Memory Allocation = A method for the OS to promise a range of available memory provided to a process in one piece.

Base Value = where process starts in memory.
Limit Value = size of process.

Memory Hole = fragmented, unusable free gaps in physical memory or unallocated regions in virtual address space.
Fragmentation = wasted memory because of inefficient memory usage.
External fragmentation vs internal fragmentation?►
External Fragmentation = a kind of fragmentation where wasted memory is not allocated for any process, where holes are too small and scattered to be useful.

Internal Fragmentation = wasted memory allocated to a process but not being used because the OS gave it more than it needed.

Doesn’t occur in CMA since the OS gives exactly how much it needs but it does happen in paging.
What is paging? Page? Frame? What fragmentation does it cause?►
Paging = a memory management technique that avoids the need for contiguous physical memory allocation. It divides both logical and physical memory into fixed, same sized chunks, then map them freely.

Page = A portion of logical address space of fixed size.
Frames = A portion of physical address space of fixed size.

Processes believe memory is stored in virtual memory but in reality is stored in physical memory (this is done after pages map stuff to frames).
What is a page table? How many per system?►
Page Table = a data structure that stores page to frame mapping for a given process.

Every process has its own page table.
Page offset? How are addresses structured in paging?►
Page Offset = how far from the beginning of the page the address is located.

Page Table = data structure that stores mapping from pages to frames for a specific process.

MMU does not need to do any arithmetic operations.

When your page size is a power of 2, the rightmost bits are the offset, the remaining bits are the page number.
Three options for MMU to deal with the page table. Disadvantages of the two we don't use?►
Store whole page table in MMU from RAM -- not a good option (slow context switch).

Keep the whole page table in RAM -- a better option, but still a bad option (doubles the amount of memory operations).

Store the currently used portion of page table in MMU.

TLB (Translation Lookaside Buffer) = a memory device in the MMU that stores the most useful page/table entries.
What is the TLB? TLB hit vs TLB miss?►
TLB Hit = a situation when a needed page table entry already exists in the buffer.

TLB Miss = where a page table entry is not found in buffer.

Locality principle = programs tend to use specific chunks of data for a bit of time before moving further.
On-demand paging? Page fault?►
On-demand Paging = a variation of a paging technique that allows to run processes that are only partially loaded in RAM.

Page Fault = a situation when required code or data is still on the hard-disk but not in RAM.
Synchronization
Race conditions, critical sections, mutex, deadlock -- all his exact definitions.
What are synchronization problems? What hazards?►
What’s important is that you need to manage interactions between threads and processes the usage of resources correctly.

Two hazards: race condition and deadlock.
What is a race condition?►
Race Condition = a scenario when a shared resource becomes corrupted because multiple threads/processes try to access this shared resource, and at least one of them tries to modify it.

Race conditions are logic errors and you may not be able to reproduce the bug, which makes them hard to debug.
How does a race condition happen at the CPU level?►
For t1 in its own CPU core on the r1 register:
LOAD glob,r1
r1 = r1+1
STORE r1,glob
These 3 instructions are the critical section of t1.

For t2 in a separate CPU core, but notice how they share the same CPU register:
LOAD glob,r1
r1 = r1+1
STORE r1,glob
These 3 instructions are the critical section of t2.

t2 should never enter t1’s critical section, t2 will stop and wait until t1 finishes all of its instructions, only then can t2 run its own critical section.
Critical Section Problem. Three properties of a good solution?►
Critical Section Problem = a problem of programming your threads/processes in such way that they do not use shared resources simultaneously.

The threads/processes are arranged to access the shared resource one at a time.

Properties:
  • Exclusivity = only 1 thread/process can access a shared resource at a time, the usage of a shared resource should be exclusive.
  • Progress = shared resource does not stay idle if somebody needs it.
  • Bounded Waiting = make sure that nobody waits forever.
What is an atomic function? (Both parts of the definition.)►
Atomic functions = hardware-implemented functions that allow us to avoid race conditions and use multi-threading and shared resources.

Two reasons:
Only one atomic function can run at a time.
All other atomic functions are paused.
They are uninterruptable.
Once it starts, it finishes it with nobody interrupting it.
What is test_and_set? Simple critical section solution. What is suboptimal?►
Atomic function example:
bool test_and_set(bool& lock) {
  bool original = lock;
  lock = true; // resource is in use, its locked
  return original;
}
A simple solution for Critical Section problem without bounded waiting property but with exclusivity:
while (test_and_set(globLock)) {};
// CRITICAL SECTION
globLock = false;
Busy waiting? Spinlock? When is it good?►
Busy Waiting = a method of waiting that requires constant CPU usage.

Inefficient because of the sole fact it uses the CPU constantly waiting.

Spinlock = a synchronization tool that implements busy waiting under the hood.
What is a mutex? What if it is busy?►
Mutex = (mutual exclusion lock).

std::mutex m;
m.lock(); // I WANT TO ACQUIRE THE LOCK, WAIT TILL ITS UNLOCKED, WAIT TILL THE RESOURCE IS IDLE, YOU DONT NEED ANY WHILE LOOPS TO IMPLEMENT THIS, ALL THE WAITING WILL BE IMPLEMENTED FOR YOU
// CRITICAL SECTION
// then release the lock for everybody else
m.unlock();
Producer-Consumer (Bounded Buffer) problem and solution.►
Bounded buffer problem == Producer-Consumer problem

When the buffer is full, the producer should pause its operations.
When the buffer is empty, the consumer should pause its operations.

Semaphore FULL = 0; // counts the number of items in the buffer
Semaphore EMPTY = N; // number of empty spaces

// For Producers
wait(EMPTY);
signal(FULL);

// For Consumers
wait(FULL);
signal(EMPTY);
Readers-Writers problem and solution.►
Another synchronization problem → Readers-Writers problem

We know that we want to avoid race conditions here, there is no harm in readers reading shared data simultaneously.

Readers solution:
read_guard.lock();
num_readers++;
if (num_readers == 1) access.lock();
read_guard.unlock();
// start reading
// done reading
read_guard.lock();
num_readers--;
if (num_readers == 0) access.unlock();
read_guard.unlock();
Writers solution:
access.lock();
// writing
access.unlock();
Dining Philosophers problem. Philosophers = ? Chopsticks = ? Three solutions?►
Another synchronization problem → Dining Philosophers problem

Chopsticks represent locks controlling the shared resources (mutex locks in reality).

Deadlock → a scenario when multiple threads/processes block each other and nobody progresses forward.

Methods to avoid Deadlock:
  • Add extra chopstick
  • Pick chopsticks simultaneously
  • Asymmetric solution
What is deadlock?►
Deadlock = a scenario when multiple threads/processes block each other and nobody progresses forward.

Fork Practice
Both midterms had a fork question worth 15 points. Practice until this is automatic.
Key rules: fork() returns 0 to child, positive PID to parent. After fork(), BOTH processes continue from the next instruction. Order between processes is NOT guaranteed. if(fork()) = parent runs if-body. if(!fork()) = child runs if-body.
Problem 1 -- Straight forks, no if
fork(); // A
cout << "1" << endl;
fork(); // B
cout << "2" << endl;
How many total processes run?
How many times is "1" printed?
How many times is "2" printed?
Walk-through:
Original and Child-A both continue after fork A.
fork B fires in both processes. Each child of B just prints "2" and finishes. Each parent of B prints "1" then "2".

Process tree:
Original
  Child-of-A
    Child-of-B-from-Child-A
  Child-of-B-from-Original
Total processes: 4
"1" is printed 2 times.
"2" is printed 4 times.
One valid output: 12 12 2 2
Problem 2 -- If/else fork logic
if (fork()) // A
    cout << "1" << endl;
else {
    fork(); // B
    cout << "2" << endl;
}
cout << "3" << endl;
How many total processes run?
Which process(es) print "1"?
Give one possible output
Walk-through:
Fork A: Original (parent) enters if-body and prints "1". Child-of-A goes to else and prints "2" then hits fork B.
Fork B only happens in the else-block.
Since cout "3" is outside the if-else, every process prints "3".

Process tree:
Original
  Child-of-A
    Child-of-B
Total processes: 3
"1" is printed by the original (parent) only.
One valid output: 13 23 23
Problem 3 -- From midterm version 4
fork(); // A
cout << "1" << endl;
if (fork() > 0) { // B
    fork(); // C
    cout << "2" << endl;
}
cout << "3" << endl;
How many total processes run (including the original)?
How many times is "1" printed?
Give one possible output
Walk-through:
Fork A fires. Original and Child-A both continue. Both print "1".
Fork B fires in both Original and Child-A. For each: parent side enters the if-block and does fork C then prints "2" then "3". Child side does not enter if-block and just prints "3".
Fork C fires only inside the if-block. Parent of C prints "2" then "3". Child of C just prints "3".

Process tree:
Original           -- prints 1, 2, 3
  Child-of-A        -- prints 1, 2, 3
    Child-of-C-from-Child-A -- prints 3
  Child-of-B-from-Original  -- prints 3
  Child-of-C-from-Original  -- prints 3
  Child-of-B-from-Child-A   -- prints 3
Total processes: 6
"1" is printed 2 times.
One valid output: 123 123 3 3 23 3
Problem 4 -- From midterm version 3
if (fork() != 0) { // A
    cout << "1" << endl;
} else {
    cout << "2" << endl;
    fork(); // B
}
fork(); // C
cout << "3" << endl;
How many total processes run?
Which process(es) print "1"?
Give one possible output
Walk-through:
Fork A: Original (parent, fork != 0 is true) enters if-body and prints "1". Child-of-A (fork == 0, goes to else) prints "2" then hits fork B.
Fork B: Only in the else-block. Child-of-A and its new Child-of-B both continue.
Fork C: Outside the if-else, runs in ALL processes. Original, Child-of-A, and Child-of-B all hit fork C, each spawning one more child. Every process prints "3".

Process tree:
Original                  -- prints 1, 3
  Child-of-A               -- prints 2, 3
    Child-of-B              -- prints 3
      Child-of-C-of-B       -- prints 3
    Child-of-C-of-A         -- prints 3
  Child-of-C-of-Original   -- prints 3
Total processes: 6
"1" is printed by the original (parent) only.
One valid output: 13 23 3 3 3 3
Problem 5 -- From midterm version 2
cout << "1" << endl;
if (fork()) { // A -- parent enters if, child enters else
    cout << "2" << endl;
} else {
    fork(); // B
    fork(); // C
}
cout << "3" << endl;
How many total processes run?
How many times is "1" printed?
Give one possible output
Walk-through:
"1" runs before any fork -- so only the original process prints it. Then fork A fires.
Original (parent, fork() truthy) enters if-body: prints "2" then "3".
Child-of-A (fork() = 0, falsy) enters else-body: hits fork B, then fork C.
Fork B: Child-of-A spawns Child-of-B. Both continue to fork C.
Fork C fires in Child-of-A AND Child-of-B, spawning two more processes.
Everyone eventually reaches cout "3".

Process tree:
Original                -- prints 1, 2, 3
  Child-of-A             -- prints 3 (hits B and C in else)
    Child-of-B            -- prints 3
      Child-of-C-of-B     -- prints 3
    Child-of-C-of-A       -- prints 3
Total: 5 processes.
"1" prints 1 time (before any fork).
"3" prints 5 times (every process reaches it).
One valid output: 123 3 3 3 3

Review -- Fundamentals
These are the "Review Old Items" from the study guide. Know these cold -- they are fair game on a cumulative final.
What is a program? What is data?►
Program = A static list of CPU instructions stored in an executable file. It does not change.

Data = Information stored and processed by a computer. Data and program instructions are both stored in RAM and on disk as bits and bytes.
What does it mean to run a program? What component executes it? Where are running programs stored?►
Running a program means loading its instructions from disk into RAM and having the CPU fetch and execute those instructions one by one via the machine cycle.

Running programs are stored in RAM. RAM also stores the program's data -- variables, the stack, heap, etc. Programs are NEVER executed directly from disk.
What do we know about RAM? What is a memory stall?►
RAM (Random Access Memory) = Fast, volatile (loses data when power off), temporary storage. Programs must be in RAM to execute. Much faster than hard disk but much slower than CPU registers.

Memory stall = A delay in CPU execution that occurs when the CPU has to wait for data to be fetched from RAM. Because RAM is slow relative to the CPU, the CPU idles during this wait. This is why cache memory exists.
What is cache memory? What is its purpose?►
Cache memory = A small, extremely fast memory built into or very close to the CPU. Its purpose is to reduce memory stalls by storing recently or frequently accessed data so the CPU does not have to wait for slow RAM as often.

Cache is much faster than RAM but much smaller. When the CPU needs data, it checks cache first (cache hit = fast) before going to RAM (cache miss = slow).
What is ROM memory? What does it store?►
ROM (Read-Only Memory) = Non-volatile memory that retains data without power. It stores the firmware -- the very first code that runs when you turn on a computer (like the BIOS/UEFI). The CPU reads from ROM at startup to begin the boot process. Unlike RAM, you cannot write to ROM during normal operation.
What is an executable file?►
Executable file = A file stored on disk that contains machine code (CPU instructions) for a program, along with any data the program needs to start. When you "run" a program, the OS reads this file and loads it into RAM to create a process.
How do speeds of CPU, RAM and hard disk compare?►
From fastest to slowest:

CPU registers = fastest (nanoseconds, part of the CPU itself)
Cache = very fast (slightly slower than registers)
RAM = fast but much slower than CPU (tens of nanoseconds -- causes memory stalls)
Hard disk (HDD) = extremely slow compared to RAM (milliseconds -- orders of magnitude slower)
SSD = between HDD and RAM but still much slower than RAM

This hierarchy is why programs must be in RAM to run efficiently -- disk access during execution would be catastrophically slow.
What is a machine cycle? What are its steps?►
Machine cycle = The basic sequence the CPU repeats continuously to execute a program. Also called the fetch-decode-execute cycle.

Steps:
  • Fetch = CPU reads the next instruction from RAM at the address stored in the Program Counter (PC)
  • Decode = CPU figures out what the instruction means
  • Execute = CPU carries out the instruction
  • PC increments to point to the next instruction, then repeat
What is CPU frequency? What does it measure? What is a CPU clock? What is a CPU core?►
CPU clock = An electronic signal that pulses at a fixed rate, synchronizing all operations inside the CPU.

CPU frequency = The number of clock cycles per second. Measured in Hz (hertz). Modern CPUs run at gigahertz (GHz) -- billions of cycles per second. Higher frequency = more instructions executed per second (roughly).

CPU core = An independent processing unit within the CPU that can execute instructions. A quad-core CPU has 4 cores (can run 4 streams of instructions simultaneously). An octa-core has 8 cores.
What is a byte? What is a bit? How many bits in a byte? How many bits in 1 KB?►
Bit = The smallest unit of data. Either 0 or 1.

Byte = 8 bits. The standard unit of memory addressing.

1 KB = 1,024 bytes = 1,024 x 8 = 8,192 bits.

Memory sizes: 1 KB = 1,024 bytes / 1 MB = 1,024 KB / 1 GB = 1,024 MB / 1 TB = 1,024 GB.
What is a memory address? What is the address of a larger chunk of memory?►
Memory address = A unique number that identifies a specific byte in RAM. Every byte has its own address.

Address of a larger chunk = The address of its first byte. For example, if an int takes 4 bytes starting at address 1000, the address of that int is 1000 (pointing to the first byte).
What is the length of a memory address? What does "32-bit address" mean? How much memory can you address?►
Length of a memory address = The number of bits used to represent an address.

32-bit address = Each address is 32 bits long. With 32 bits you can represent 2^32 unique addresses = 4,294,967,296 = about 4 GB of addressable memory. This is why old 32-bit systems were limited to 4 GB of RAM.

64-bit address = 2^64 unique addresses = an astronomically large amount of memory (16 exabytes -- far more than any current system has).

Formula: with N-bit addresses you can address 2^N bytes.
What is the relationship between a C++ variable, RAM and memory address? What is a C++ pointer?►
When you declare a variable in C++, the compiler allocates space for it in RAM (on the stack or heap). The variable has a memory address -- the location of its first byte in RAM.

C++ pointer = A variable that stores a memory address (instead of a regular value like an int or char). It "points to" another variable's location in RAM. You get the address of a variable with &x and you access the value at an address with *ptr.
Common sizes of C++ data types. Does signed/unsigned affect size?►
  • char = 1 byte (8 bits)
  • short = 2 bytes (16 bits)
  • int = 4 bytes (32 bits)
  • long = 4 or 8 bytes (platform-dependent)
  • long long = 8 bytes (64 bits)
  • float = 4 bytes (32 bits)
  • double = 8 bytes (64 bits)
Signed/unsigned does NOT affect size -- int, signed int, and unsigned int are all 4 bytes. Signed/unsigned only affects the range of values (signed can be negative, unsigned cannot but gets double the positive range).
Hexadecimal numbers -- why do we use them? How do we convert hex to binary quickly?►
Why hex? = Hexadecimal (base 16) is a compact way to represent binary. Each hex digit maps exactly to 4 binary bits, making it much shorter than binary to write while still being easy to convert.

Quick conversion = Replace each hex digit with its 4-bit binary equivalent:
0=0000  1=0001  2=0010  3=0011
4=0100  5=0101  6=0110  7=0111
8=1000  9=1001  A=1010  B=1011
C=1100  D=1101  E=1110  F=1111
Example: 0xFF = 1111 1111 = 255 in decimal.
Example: 0x1A = 0001 1010 = 26 in decimal.
What is "little-endian"? (appeared on version 2 midterm)►
Endianness = The order in which bytes of a multi-byte value are stored in memory.

Little-endian = The least significant byte (the smallest part) is stored at the lowest memory address. Most modern CPUs (including x86/x64) use little-endian.

Example: the int value 0x12345678 stored at address 1000:
  • Address 1000: 0x78 (least significant)
  • Address 1001: 0x56
  • Address 1002: 0x34
  • Address 1003: 0x12 (most significant)
Big-endian = Most significant byte at lowest address (the "natural" reading order).
What is a word? What is the PC (Program Counter)?►
Word = The natural data size the CPU processes in one operation. On a 32-bit system a word is 4 bytes; on a 64-bit system a word is 8 bytes.

Program Counter (PC) = A special CPU register that holds the memory address of the next instruction to be fetched and executed. After each instruction, the PC automatically increments to point to the next one. It is saved and restored during context switches.
What language does the CPU understand? How do we run higher-level programs?►
The CPU only understands machine code -- binary instructions specific to that CPU architecture (like x86-64).

Higher-level programs (C++, Python, Java) are run by:
  • Compilation (C, C++) -- a compiler translates source code entirely into machine code before running. Fast at runtime.
  • Interpretation (Python) -- an interpreter reads and executes source code line by line at runtime. Portable but slower.
  • Both (Java) -- compiled to bytecode first, then interpreted/JIT-compiled by the JVM at runtime.
Stack overflow -- what is it and what causes it?►
The stack has a fixed size limit set by the OS. If a program exceeds this limit (usually from infinite or very deep recursion, or allocating too many large local variables), the stack runs out of space.

This causes a stack overflow, which crashes the program. This is why you should not allocate very large arrays as local variables -- put them on the heap with new instead.
Do processes physically move in RAM when their state changes?►
No. When a process changes state (e.g., from Running to Waiting), the OS simply updates the state field in its PCB. The process stays in the exact same location in RAM throughout.

Visualizations that show processes physically moving between boxes (like moving into the I/O queue box) are simplifications for clarity. No actual movement of data in RAM happens. The "queues" are just lists of PCB references maintained by the OS.
Copy-on-write optimization for fork() + exec()►
When fork() is called, the OS creates a copy of the process -- but making a full copy of all memory is expensive.

Copy-on-write (COW) = An optimization where the OS does NOT immediately copy the memory on fork(). Instead, both parent and child share the same memory pages, marked as read-only. A copy is only made when one of them tries to write to a page.

This is especially useful when fork() is immediately followed by exec(), because exec() replaces all memory anyway -- so no copy was ever needed. The OS detects this and skips copying entirely.
Ready queue -- one per core, not per system?►
The guide specifies: there is typically one ready queue per CPU core. Shostak's class notes say one ready queue per system.

For the exam, use Shostak's definition: one ready queue in the system. This note reflects how modern multi-core schedulers actually work, but Shostak tests on his definition.
