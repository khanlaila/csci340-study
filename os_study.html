OS Basics, Programs and CPU
Fundamentals tested on every exam.
What is an Operating System?►
OS Definition = A program that manages hardware and provides other programs with an environment to run in.
What is the OS Kernel?►
OS Kernel = A central component of the OS that performs the most important OS tasks.

Monolithic Kernel = An OS architecture where the entire OS runs together in a single kernel space, allowing high performance due to efficient communication.

Microkernel = Where the kernel performs a more minimal set of functions.
List all OS functions with short descriptions.►
  • Running programs -- finds executable, loads to RAM, runs it, stops it when done
  • IPC -- tools that allow programs to exchange data
  • Managing CPU -- controls which process uses the CPU and for how long (multitasking)
  • Managing RAM -- decides where in RAM each program lives; uses virtual memory when RAM fills up
  • Managing I/O -- collects hardware input and passes to app; uses interrupts and drivers
  • Managing Storage -- all file operations go through OS; uses file systems and logical disks
  • Managing Networking -- apps ask OS to send/receive data; OS uses networking protocols
  • User Interface -- GUI (icons, clicking) or Command-Driven (typing)
  • Security -- prevents misuse, tracks who is logged in and their privileges
What is multitasking? How is it arranged?►
Multitasking = A technique to fake simultaneous executions of multiple processes on a single CPU core.

Classic CPU cores only execute one program at a time. The OS runs portions of one program, switches to another via a context switch, then another. If this happens fast enough, programs appear to run simultaneously. In reality, only one program runs at a given time on a single core.
What are user mode and kernel mode? Why do we have dual modes?►
User Mode = Can only execute safe (user-level) instructions. If a user-mode program tries a kernel-level instruction, the CPU refuses and alerts the OS.

Kernel Mode = Can execute ALL instructions including unsafe ones (I/O, memory management, hardware). OS components run here.

The CPU switches automatically to kernel mode when a system call happens, then switches back.

Why dual modes? = For safety and stability -- separating user applications from critical hardware operations.
What is a system call? Why is it slow?►
System Call = A request for service from a user-level application to the OS.

Why slow? = A syscall causes 2 context switches (to OS and back). Each requires saving and loading CPU registers to/from RAM. RAM is slow compared to the CPU.
What is virtual memory?►
Virtual Memory = A technique to fake larger RAM using the hard disk. Portions of programs not currently needed are copied to the hard disk. When needed, they are copied back to RAM. Programs still only run from RAM -- disk is overflow storage. Expensive performance-wise.
What are interrupts? What are interrupt handlers? What is the sequence when one arrives?►
Interrupt = A signal about some important event that requires immediate attention.

Sequence: interrupt generated (e.g. keypress) -- signal reaches CPU -- CPU pauses all current activity -- CPU runs the interrupt handler (ISR), a special function for this event -- handler finishes -- interrupt cleared -- CPU resumes. There exist maskable (can be ignored) and unmaskable (cannot) interrupts.
What is a driver?►
Driver = A small program that handles communications between the OS and devices. Allows the OS to work with I/O devices including ones that did not exist when the OS was written.
What is a file? File system? Logical disk?►
File = A bunch of related data stored on a hard disk under one name.

File System = A collection of data about all files on a computer including physical coordinates of files on the hard disk. Stores descriptions of files, not the files themselves.

Logical Disk / Partition = A portion of a hard disk described in a separate file system. Example: drive C and drive D on one physical hard disk.
What is an interpreter? Advantage? What is a compiler? Advantage?►
Interpreter = Executes code line by line at runtime. No pre-compilation. Advantage = portability -- same code runs on any machine with the interpreter. Examples: Python, JavaScript.

Compiler = Translates entire source code into machine code before it runs. Advantage = speed -- code is already machine code when executed. Examples: C, C++.
How many bits are in 1 KB of data?►
1 byte = 8 bits. 1 KB = 1,024 bytes. So 1 KB = 1,024 x 8 = 8,192 bits.
What is POSIX? What is the OS API?►
POSIX = A standard for maintaining compatibility between operating systems. Functions like fork(), exec(), exit(), wait() come from POSIX and work on Linux (not Windows).

OS API = A set of tools the OS provides for programmers. It does system calls under the hood so programmers do not need to make raw syscalls directly.
Processes
PCB, process states, fork/exec/exit/wait, zombies, orphans, IPC
What is a process? How is it different from a program?►
Process = A program in execution. Program = A static set of instructions stored on the hard disk. A program is passive (just code on disk). A process is active (loaded into RAM, being executed by the CPU). One program can have multiple processes.
What is the PCB? Typical components?►
PCB (Process Control Block) = A record for a single process maintained by the OS. Typically less than 1 KB.

Components: PID, parent PID, process state, CPU scheduling info, memory management info, list of opened files, list of requested I/O devices, register file, program counter.
List the five process states and describe each.►
  • New = Created (PCB exists), not yet ready. Code/data still loading from disk.
  • Ready = In ready queue, willing and able to use CPU, waiting for permission.
  • Running = Currently using the CPU.
  • Waiting = Requested I/O, waiting for it to complete. Not using CPU. Goes back to Ready when done.
  • Terminated = Done. Resources released. PCB may remain briefly (zombie state).
Ready queue vs I/O queue. How many of each?►
Ready Queue = A collection of processes ready and willing to use the CPU. There is one ready queue in the system.

I/O Queue = A collection of processes waiting to use an I/O device. There is one I/O queue for each I/O device.
What happens when a process requests I/O (blocking)? Where does it go after?►
Process stops using the CPU, joins that device's I/O queue, enters Waiting state. CPU switches to another process. Once I/O completes, process goes back to the Ready Queue.
What is a context switch? Why does it have overhead?►
Context Switch = Steps the CPU takes to switch execution from one process to another: pause P1 -- save CPU registers and PC of P1 to RAM -- load CPU registers and PC of P2 from RAM -- resume P2.

Overhead because it requires 2 RAM operations and RAM is slow compared to the CPU. Syscalls are expensive because each causes 2 context switches.
Layout of a process in memory. Describe each section.►
  • Text Section = Program code (instructions).
  • Data Section = Global variables and static variables.
  • Heap = Dynamic memory (new operator). Fragmented, full of holes.
  • Stack = Local variables, function parameters, return addresses. Clean LIFO order, no holes. Each thread has its own stack.
What is fork()? Return values?►
fork() = Creates an almost exact copy of the process. Original = Parent. Copy = Child.

Returns 0 to child. Returns positive PID value to parent. After fork, both processes continue from the next instruction concurrently. Order is not guaranteed.
What is exec()? exit()? wait()?►
exec("name") = Erases all process content and starts a new program from an executable file. Typically used in child after fork().

exit() = Stops the process, reports exit status (0 = success), releases resources. Code after exit() does not run. PCB stays -- process becomes zombie until parent calls wait().

wait() = Called by parent to pause until child terminates. Receives child's exit status. Parent then continues.
Zombie process? Orphan process? Why are orphans bad?►
Zombie = Called exit() but parent has not called wait() yet. No resources, but PCB remains.

Orphan = Parent exited without calling wait(). Bad because nobody can collect exit status. System either adopts orphans or uses cascading termination (kill all descendants when parent exits).
What is IPC? Two general classes?►
IPC = Tools that allow processes to exchange data.

Message Passing = Pass message to OS, OS delivers to other process. Slower (syscall), safer, works across different computers.

Shared Memory = Processes share a memory region directly. Faster (OS help only once), harder to program correctly, same computer only.
Threads and Networking
Threads vs processes, DNS, ports, sockets, std::thread
What is a thread? What do threads share vs not share?►
Thread = An independent execution of program code from a separate program counter.

Threads SHARE: text section, data section, heap.

Threads do NOT share: stack (each thread has its own -- local variables and function params are private).
Why create threads instead of processes?►
Memory efficient (code/heap/data not copied), fast to create, faster context switch, shared memory by default, overall less OS overhead compared to processes.
Why create processes instead of threads?►
Processes can run exec() to start a completely different program. Processes are fault-independent -- if one crashes, others keep running. If one thread crashes, the entire process and all its threads stop. Example: Chrome tabs are separate processes.
TLS? Thread pool? How to create a thread with std::thread?►
TLS (Thread Local Storage) = Variables that are global but private per thread.

Thread Pool = Threads created in advance and put to sleep. Reused when needed instead of creating new ones. Avoids overhead of repeated creation/destruction.

#include <thread>
std::thread t1{Foo, 5};
std::thread t2{Foo, 56};
t1.join(); // wait for t1
t2.join(); // wait for t2
join() = Makes the calling thread wait until the specified thread finishes.
What is an IP address? Why is it not enough alone?►
IP Address (IPv4) = Each number is an unsigned byte (0 to 255), written as 4 numbers separated by dots. Identifies a computer on a network.

Not enough alone because a computer runs many programs simultaneously. IP only identifies the computer, not which program should receive the message. That is what a port number is for.
Networking port? Well-known ports?►
Networking Port = A unique numeric identifier given to every process that wants to use the network. IP address + port = full network address.

Well-Known Ports = Ports reserved for a specific purpose. Example: port 80 is reserved for HTTP. Browsers know to connect on port 80 for web pages without being told.

Shostak warning: Saying "first 1024 ports" = 0 points. Describe their purpose.
What is a network socket? What is DNS?►
Network Socket = A combination of an IP address and a networking port.

DNS = DNS servers function as the internet's phonebook, translating human-readable domain names into machine-readable IP addresses.
Memory Management
Physical vs logical addresses, MMU, paging, TLB, page faults
Physical address vs logical address. How many of each exist?►
Physical address = The real address of the actual RAM device. Extremely inconvenient for programming (changes every run, processes would conflict).

Logical (Virtual) address = The address a process uses in its instructions, as if it owns all memory starting from 0.

Physical address spaces: 1 (one RAM device). Logical address spaces: one per process.
What kind of address does the CPU use? What arrives at RAM?►
CPU uses logical addresses in instructions. The MMU translates them. Physical addresses arrive at RAM.
What is the MMU?►
MMU (Memory Management Unit) = A device that converts logical addresses to physical addresses. Sits on the address bus between CPU and RAM. The OS tells the MMU about each process before running it so it can translate addresses correctly.
What is contiguous memory allocation? What fragmentation?►
Contiguous Memory Allocation (CMA) = OS provides each process a continuous range of memory in one piece. MMU uses Base (start) and Limit (size) values to check if addresses are legal.

Suffers from external fragmentation = holes of free memory too small and scattered to fit new processes.
External fragmentation vs internal fragmentation?►
Fragmentation = Wasted memory from inefficient usage.

External = Free memory NOT allocated to any process -- holes too small and scattered to be useful. (CMA problem.)

Internal = Memory allocated TO a process but not used -- OS gave more than needed. (Paging problem.)
What is paging? Page? Frame? What fragmentation does it cause?►
Paging = A memory management technique that avoids contiguous physical memory allocation. Divides both logical and physical memory into fixed same-sized chunks and maps them freely.

Page = A portion of logical address space of fixed size. Frame = A portion of physical address space of fixed size. Pages and frames are the same size.

Suffers from internal fragmentation -- must give full pages even if only part is needed. Larger page size = more internal fragmentation.
What is a page table? How many per system?►
Page Table = A data structure storing page-to-frame mappings for a process. Tells MMU which physical frame corresponds to each logical page. There is one page table per process.
Page offset? How are addresses structured in paging?►
Page Number = floor(logical address / page size)
Page Offset = logical address % page size
Physical Address = (frame number x page size) + offset
Three options for MMU to deal with the page table. Disadvantages of the two we don't use?►
Option 1: Store whole table in MMU hardware. Disadvantage: page tables can be huge -- not enough memory built into the MMU.

Option 2: Keep whole table in RAM. Disadvantage: every memory access needs an extra RAM lookup -- doubles access time. RAM is slow.

Option 3 (what we use): TLB -- cache the most recently used page table entries in MMU. Uses locality principle.
What is the TLB? TLB hit vs TLB miss?►
TLB (Translation Lookaside Buffer) = A memory device inside the MMU storing the most useful page table entries. Like a cache for the page table. Uses LRU policy.

TLB Hit = Needed entry already in TLB. Fast -- no extra RAM lookup.

TLB Miss = Entry not in TLB. MMU must go to RAM to find it, copies entry to TLB (extra RAM trip -- slow).

Locality Principle = Programs tend to use specific memory chunks for a while before moving on. Makes TLB hits common.
On-demand paging? Page fault?►
On-Demand Paging = A variation of paging that allows running processes that are only partially loaded in RAM. Only what is needed right now is loaded; rest stays on disk until needed.

Page Fault = A situation when required code or data is on the hard disk but not in RAM. Program pauses while OS copies the missing page from disk to RAM. Expensive because disk access is very slow.
Synchronization
Race conditions, critical sections, mutex, deadlock -- all his exact definitions.
What are synchronization problems? What hazards?►
Synchronization problems = Programming problems that arise when you create multithreaded code or a program that exchanges data with another program.

Two hazards: race condition and deadlock.
What is a race condition?►
Race Condition = A scenario when a shared resource becomes corrupted because multiple threads/processes try to access this shared resource, and at least one of them tries to modify it. Race conditions are logic errors that may not be reproducible.
How does a race condition happen at the CPU level?►
Even glob++ compiles to 3 CPU instructions:
LOAD glob, r1    ; read glob into register
r1 = r1 + 1      ; add 1
STORE r1, glob   ; write back
If thread t1 does LOAD (gets 5), gets paused, t2 runs fully (writes 6), then t1 resumes and STORE its old r1 (writes 6 instead of 7) -- one increment is lost.

If everybody only reads: no race condition. If one modifies and others read: yes, can happen.
Critical Section Problem. Three properties of a good solution?►
Critical Section Problem = A problem of programming threads/processes such that they do not use shared resources simultaneously.

Three properties:
  • Exclusivity = Only 1 thread/process can access a shared resource at a time.
  • Progress = Shared resource does not stay idle if somebody needs it.
  • Bounded Waiting = Nobody waits forever. Hard limit on how many others enter before a waiting process gets its turn.
What is an atomic function? (Both parts of the definition.)►
Two properties:
  • Only one atomic function can run at a time -- all other atomic functions are paused.
  • Uninterruptible -- once it starts, it finishes.
Hardware-implemented = No program code for it, no CPU instructions in memory. Implemented with hardware circuitry, called with a single special CPU instruction.
What is test_and_set? Simple critical section solution. What is suboptimal?►
Hardware atomic function -- atomically checks and sets a lock:
bool test_and_set(bool& lock) {
  bool original = lock;
  lock = true;      // always sets to locked
  return original;  // returns what it WAS
}
Simple solution:
while (test_and_set(globLock)) {};
// CRITICAL SECTION
globLock = false;
Suboptimal: Does NOT have bounded waiting -- not starvation-free. A thread could wait forever.
Busy waiting? Spinlock? When is it good?►
Busy Waiting = A method of waiting that requires constant CPU usage (looping while checking).

Spinlock = A synchronization tool that implements busy waiting under the hood.

When still good: When expected wait times are short and it is cheaper to wait while using CPU than to perform a context switch to another process.
What is a mutex? What if it is busy?►
Mutex = Mutual exclusion lock.

If the mutex is busy: the process pauses somehow and waits for the mutex to be free again before proceeding further. The OS puts it to sleep and wakes it up when the mutex becomes available (non-busy-waiting).
std::mutex m;
m.lock();    // acquire -- waits if busy
// CRITICAL SECTION
m.unlock();  // release for others
Producer-Consumer (Bounded Buffer) problem and solution.►
Problem: Producer creates items into a fixed-size buffer. Consumer takes items. Producer pauses when full. Consumer pauses when empty.

Solution with 2 semaphores:
Semaphore FULL = 0;  // # of items
Semaphore EMPTY = N; // # of spaces

// PRODUCER:
wait(EMPTY); // wait for space
// place item
signal(FULL); // signal item available

// CONSUMER:
wait(FULL);  // wait for item
// take item
signal(EMPTY); // signal space freed
Readers-Writers problem and solution.►
Problem: Shared data, readers can read simultaneously, writers must have exclusive access one at a time.

Solution:
mutex access;     // controls exclusive write access
int num_readers = 0;
mutex read_guard; // protects num_readers

// READERS:
read_guard.lock();
num_readers++;
if (num_readers == 1) access.lock(); // first reader locks writers out
read_guard.unlock();
// READ
read_guard.lock();
num_readers--;
if (num_readers == 0) access.unlock(); // last reader lets writers in
read_guard.unlock();

// WRITERS:
access.lock();
// WRITE
access.unlock();
Dining Philosophers problem. Philosophers = ? Chopsticks = ? Three solutions?►
N philosophers at a table. One chopstick between each pair. Need BOTH to eat. Alternate thinking and eating.

Philosophers = Threads or processes competing for resources.

Chopsticks = Mutex locks controlling shared resources.

The danger: All grab left chopstick simultaneously -- nobody can grab right -- deadlock.

3 approaches:
  • Allow only N-1 philosophers to sit at once
  • Only pick up both chopsticks if BOTH are available (atomically)
  • Asymmetric -- odd-numbered pick left then right; even-numbered pick right then left
What is deadlock?►
Deadlock = A scenario when multiple threads/processes block each other and nobody progresses forward. Can happen with as few as 2 threads and 2 resources.

Fork Practice
Both midterms had a fork question worth 15 points. Practice until this is automatic.
Key rules: fork() returns 0 to child, positive PID to parent. After fork(), BOTH processes continue from the next instruction. Order between processes is NOT guaranteed. if(fork()) = parent runs if-body. if(!fork()) = child runs if-body.
Problem 1 -- From midterm version 4
fork(); // A cout << "1" << endl; if (fork() > 0) { // B fork(); // C cout << "2" << endl; } cout << "3" << endl;
How many total processes run (including the original)?
How many times is "1" printed?
Give one possible output
Walk-through:
Fork A fires. Original and Child-A both continue. Both will print "1".
Fork B fires in both Original and Child-A. For each: parent side (fork > 0) enters the if-block and does fork C then prints "2" then "3". Child side does not enter if-block and just prints "3".
Fork C fires only inside the if-block. Parent of C prints "2" then "3". Child of C just prints "3".

Process tree:
Original           -- prints 1, 2, 3
  Child-of-A        -- prints 1, 2, 3
    Child-of-C-from-Child-A -- prints 3
  Child-of-B-from-Original  -- prints 3
  Child-of-C-from-Original  -- prints 3
  Child-of-B-from-Child-A   -- prints 3
Total processes: 6
"1" is printed 2 times (Original and Child-A before fork B).
One valid output: 123 123 3 3 23 3
Problem 2 -- From midterm version 3
if (fork() != 0) { // A cout << "1" << endl; } else { cout << "2" << endl; fork(); // B } fork(); // C cout << "3" << endl;
How many total processes run?
Which process(es) print "1"?
Give one possible output
Walk-through:
Fork A: Original (parent, fork != 0 is true) enters if-body and prints "1". Child-of-A (fork == 0, goes to else) prints "2" then hits fork B.
Fork B: Only in the else-block. Child-of-A and its new Child-of-B both continue.
Fork C: Outside the if-else, runs in ALL processes. Original, Child-of-A, and Child-of-B all hit fork C, each spawning one more child. Every process prints "3".

Process tree:
Original                  -- prints 1, 3
  Child-of-A               -- prints 2, 3
    Child-of-B              -- prints 3
      Child-of-C-of-B       -- prints 3
    Child-of-C-of-A         -- prints 3
  Child-of-C-of-Original   -- prints 3
Total processes: 6
"1" is printed by the original (parent) only.
One valid output: 13 23 3 3 3 3

  Child-of-A   -- prints 1, 2

  Child-of-B-from-Original  -- prints 2 only
Total: 4 processes. "1" prints 2 times. "2" prints 4 times.

Problem 4 -- Practice (if/else fork logic)
if (fork()) // A -- parent enters if, child enters else cout << "1" << endl; else { fork(); // B cout << "2" << endl; } cout << "3" << endl;
How many total processes run?
Give one valid possible output
Walk-through:
Fork A: Original gets positive return (truthy) -- enters if, prints "1" then "3".
Child-of-A gets 0 (falsy) -- enters else, hits fork B, prints "2" then "3".
Child-of-B: starts after fork B in the else-block, prints "2" then "3".

Total: 3 processes.

Problem 5 -- From midterm version 2
cout << "1" << endl; if (fork()) { // A -- parent enters if, child enters else cout << "2" << endl; } else { fork(); // B fork(); // C } cout << "3" << endl;
How many total processes run?
How many times is "1" printed?
Give one possible output
Walk-through:
"1" runs before any fork -- so only the original process prints it. Then fork A fires.
Original (parent, fork() truthy) enters if-body: prints "2" then "3".
Child-of-A (fork() = 0, falsy) enters else-body: hits fork B, then fork C.
Fork B: Child-of-A spawns Child-of-B. Both continue to fork C.
Fork C fires in Child-of-A AND Child-of-B, spawning two more processes.
Everyone eventually reaches cout "3".

Process tree:
Original                -- prints 1, 2, 3
  Child-of-A             -- prints 3 (hits B and C in else)
    Child-of-B            -- prints 3
      Child-of-C-of-B     -- prints 3
    Child-of-C-of-A       -- prints 3
Total: 5 processes.
"1" prints 1 time (before any fork).
"3" prints 5 times (every process reaches it).
One valid output: 123 3 3 3 3
